# 2D 图形、精灵与程序化纹理

用于代码绘制的图标、精灵、背景、UI 装饰和贴图。以下是选择依据，不要求每个资产使用全部技术。

## 从输出尺寸设计

- 先确定显示尺寸、像素密度、透明需求、背景颜色和缩放方式。在最终尺寸检查，放大图不能证明小图标可读。
- 图标先定独特轮廓和内部负形，再增加分面、描边或高光。稀有度、阵营等共同语义采用统一视觉规则，不能只靠颜色区别必须识别的状态。
- 同组资产统一光线方向、透视、占画布比例、边缘处理和透明留白。形状相似的资产通过比例与结构区分，不只换色。

## 绘制组织

- 用语义分层组织代码：主体路径、结构分件、材料区域、阴影、高光、标识。把可修改的形体参数与绘制操作分开，避免大量无解释的散落坐标。
- 曲线轮廓、挤出感、遮挡与接触阴影往往比密集随机纹理更有价值。先确认无纹理版本仍然清楚。
- 像素风统一逻辑像素网格与缩放策略；矢量风检查曲线接缝、描边和实际栅格化结果。不把所有风格强行套进渐变与发光。
- 布局依赖锚点、归一化坐标或布局变换。背景中的可交互物与点击区域共享变换，避免画面缩放后错位。
- UI 文本和精确数值保留为可更新的界面内容。若烘焙到纹理，确认字体加载完成并处理不同文案长度。

## 纹理需要有结构依据

- 磨损跟随边缘、接触和使用区域；木纹跟随材料方向；砖缝和面板接缝跟随结构。随机数只控制有意义的变化，不平均撒满整个表面。
- 无缝纹理在四边重复预览。周期噪声、边界连续的绘制或拼接处理都可采用；只在单张中心看起来正确还不够。
- 微细节频率要在目标分辨率、纹理过滤和观看距离下保留。近看刺眼、远看消失时，检查频率与幅度，不先提高贴图尺寸。
- 透明贴图在亮暗背景下检查边缘，采用运行时一致的 alpha 处理。检查图集边距、过滤造成的邻图渗色与缩小后的可读性。
- 如果用于受光的 3D 材质，区分基础颜色、粗糙度、金属度、法线与遮蔽数据。不要把展示图的高光误当成物理材质的基础颜色；有意烘焙光照的风格应保持一致并检验动态视角。

## 动画与背景

- 精灵动画固定原点、基线和各帧画布；检查帧间跳动与脚底漂移。在动作中保持身份轮廓，不能只验收单帧。
- 分层背景按前中后景组织尺度、明度和视差。镜头可运动范围内检查边缘露空与层间穿插。
- 输出格式沿用项目。若生成过程昂贵但结果静态，可以离线导出；需要主题变化时保留 seed 与参数，避免每帧重绘静态内容。

## 微型示例：同一把剑的两个输出

背包图标需要清楚的剑身、护手、柄部比例与一致留白；在小尺寸优先保障轮廓。场景用纹理需要匹配网格 UV、材料方向与使用尺度。两者可以共享配色和装饰规则，不应直接把带背景高光的图标当成武器基础颜色贴图。
